# Tests (no hardware needed)

```bash
tests/run_all.sh          # host C++ tests + config/codegen tests, ~2 min
tests/run_all.sh --full   # + real ESP-IDF builds for every radio and all drivers
```

or the layers on their own:

```bash
make -C tests -j            # host C++ tests (ASan + UBSan)
make -C tests run T=pipeline   # only tests whose name contains "pipeline"
make -C tests SAN=          # without sanitizers (faster build)
~/esphome-venv/bin/python -m pytest tests/codegen      # needs: pip install pytest
```

Requirements: `g++` (C++20) and the ESPHome venv (`~/esphome-venv`, ESPHome 2025.10.3) with `pytest` installed.

Nothing in `components/` is changed for testing. Everything lives in this folder, which doesn't exist upstream, so rebasing onto upstream can't conflict.

## What is tested

| Layer | Where | What |
|---|---|---|
| Unit | `host/test_decode3of6.cpp`, `host/test_packet.cpp` | 3-out-of-6 decoding; `Packet` length detection from the L-field for every L (T1, C1 frame A/B), CRC errors, noise, truncated reads; `Frame` formatting |
| Meter decoding | `host/test_driver_vectors.cpp` | wmbusmeters' own test vectors (`// Test:` comments in every `driver_*.cpp`, read at run time), decoded and compared field by field. `izar` must pass; the other drivers are reported only (`WMBUS_VECTORS_VERBOSE=1` for details, `WMBUS_VECTORS_STRICT=1` to fail on them) |
| Meter component | `host/test_meter.cpp` | `wmbus_meter::Meter`: driver creation, id match, link-mode filter, deferred `on_telegram`, field lookup, `sensor`/`text_sensor` publishing |
| Simulated radio | `host/test_sx1262.cpp` | The real SX1262 driver talking SPI to a simulated chip (`host/sim/fake_sx1262.*`): full setup sequence and every parameter checked against the datasheet, `tcxo_voltage` for all 8 values, TCXO before calibration, RF switch, RX gain, BUSY timeout, buffer reads, RSSI, ultra-low-latency IRQ handling |
| End to end | `host/test_rx_pipeline.cpp` | Chip → DIO1 interrupt → RX task → queue → `Radio::loop` → meter → sensor value, with real air time (sync word, 255-byte fixed payload at 100 kbps). Idle watchdog, full queue, corrupted packets, the wmbusmeters.org link for unknown meters |
| Config / codegen | `codegen/test_*_codegen.py` | `esphome config` / `esphome compile --only-generate` on small configs: `tcxo_voltage` → generated byte, defaults, invalid values, only the selected transceiver and drivers are built, driver aliases, keys |
| Firmware build | `codegen/test_full_compile.py` (`--full`) | Real builds for SX1262, SX1276, CC1101 and `drivers: all` |

## How the host build works

The component `.cpp` files are compiled unmodified for Linux against small fakes of the ESPHome and FreeRTOS headers they include (`host/stubs/`):

- **Logging**: every `ESP_LOGx` call is recorded. Tests can check for a line, and `WMBUS_TEST_LOG=1` prints them.
- **`defer()`**: calls are queued, and `run_deferred()` stands in for the main loop.
- **Clock**: `delay()`/`millis()` use a fake clock.
- **FreeRTOS**: tasks are recorded but not run; the test calls `Radio::receive_frame()` itself. `ulTaskNotifyTake` advances the fake clock in 1 ms ticks until the (fake) ISR notifies.
- **SPI**: goes to `sim::FakeSX1262`. Its opcodes come from the Semtech datasheet, not from the driver's header.

`host/sim/wmbus_encode.*` is an independent "transmitter" (CRCs, 3-of-6 encoding, C1 framing) used to generate on-air bytes from telegrams.

## Known upstream bugs

Tests for confirmed bugs are written as `KNOWN_BUG(name, "why")`. They are expected to fail and are reported as `xfail`. If one starts passing (e.g. after a rebase brings a fix), it shows as `XPASS` and fails the run, so the marker gets removed.

| Test | Bug |
|---|---|
| `pipeline_ultra_low_latency_receives_packet` | `sync_mode: ULTRA_LOW_LATENCY`: the RX task wakes on SYNC_WORD_VALID but `read_in_task` waits only 1 tick for RX_DONE, which comes ~20 ms later (fixed 255-byte payload), so the packet is aborted. Use `NORMAL` (the default) |
| `test_meter_without_time_component` (pytest xfail) | `wmbus_meter` needs the `time` component but doesn't declare it: without `time:` the config validates and the build fails |

Fixed in this fork (now regression tests):
- **`decode3of6.cpp`** read one byte past its input on every T1 frame. `decode3of6_reads_only_its_input` checks it with an exact-size buffer.
- **`component.cpp`** `receive_frame` passed `packet->rx_data_ptr()` and `packet->rx_capacity()` (which resizes the buffer) to one call. It only worked because of argument evaluation order: the ESP32 toolchain goes left to right, x86-64 GCC right to left, which overflowed the heap. Because the host compiler is right to left, the `pipeline_*` tests fail under ASan if this comes back.

Other things the tests found or pin down:

- **Units:** only the driver's own unit works in `field:` (`total_m3`; `total_l` never publishes). The test is `meter_field_unit_must_match_driver`.
- **Leak:** `driver_mkradio3a.cpp` leaks 160 bytes per telegram. It's suppressed in `lsan.supp` because the driver isn't used here.
- **Host-only sanitizer exceptions** (see the comments in `Makefile`): `packet.cpp` passes `(size_t *)&int` to `checkWMBusFrame`. That is fine on the 32-bit ESP32, but an 8-byte write on a 64-bit host.
- **Other drivers:** 176 of 203 vectors pass. The remaining differences are in drivers this project doesn't use (`WMBUS_VECTORS_VERBOSE=1`).

## Adding tests

- A telegram from your own meter: take the hex from the `wmbusmeters.org/analyze/<hex>` log line and add it to `host/vectors.h`. That hex is the frame after CRC removal, as used by `sim::t1_on_air()`. Then use it in `test_meter.cpp` / `test_rx_pipeline.cpp`.
- New host test file: `host/test_<name>.cpp` with `#include "test.h"` and `TEST(name) { EXPECT(...); EXPECT_EQ(a, b); REQUIRE(...); }`. It is picked up automatically.
- Another radio: write a `sim::Fake<Chip>` implementing `esphome::spi::SPIDelegate` and add its `transceiver_<chip>.cpp` to `COMPONENT_SRCS` in the `Makefile`.
